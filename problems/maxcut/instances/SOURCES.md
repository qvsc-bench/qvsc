The code in this repository is MIT-licensed (see `LICENSE`). Instances in `gset/`, `biqmac/` and
`mqlib/` come from third parties and keep their original terms; please cite the sources below.
Instances generated by QvsC (`pegasus/`, `zephyr/`, `heavyhex/`, `reg3/`, `sk/`, `planted/`) are

All files use the rudy / G-set format (`n m`, then `u v w` per edge, 1-based, integer weights),
gzip-compressed, with `#` comment lines on top.

`references.csv` records, for each literature instance, the MQLib S3 key it was taken from, the
reference value, its source, and whether the source claims optimality.

**Reference values are not trusted.** They are shown as the target to beat, but `best_known` only
moves when a solution file in this repository reaches a value, and an instance is marked `optimal`
only when a verified solution meets a bound proven in this repository (CP-SAT or exhaustive search).
If a literature value is above what anyone can reproduce, the instance stays `below-reference`:
that is information too.

## Hardware-native graphs

| Family | Count | Topology | Weights |
|:--|--:|:--|:--|
| `pegasus` | 12 | D-Wave Pegasus P(m), m = 2, 3, 4, 6, 8, 16 (P16 = Advantage, 5,640 qubits), from `dwave_networkx.pegasus_graph` | random ±1, seeds `s1`, `s2` |
| `zephyr` | 10 | D-Wave Zephyr Z(m, 4), m = 2, 3, 4, 6, 12 (Z(12,4) = Advantage2, 4,800 qubits), from `dwave_networkx.zephyr_graph` | random ±1 |
| `heavyhex` | 18 | IBM coupling maps of Eagle r3 (127 qubits, `FakeSherbrooke`), Heron r1 (133, `FakeTorino`), Heron r2 (156, `FakeFez`) from `qiskit-ibm-runtime`, and generic heavy-hex lattices of distance 3–15 from `rustworkx` | random ±1 (heavy-hex is bipartite, so unit weights would be trivial) |

The full topologies (unit weights, not benchmark instances) are in `topologies/`, for anyone who
wants to embed other instances. Real devices have a few broken qubits and couplers; the instances
use the ideal graph.

Note: heavy-hex graphs are planar, and Max-Cut on planar graphs is solvable in polynomial time.
They are here because they are what IBM hardware runs natively, not because they are hard.

## Planted instances (optimum known by construction)

| Construction | Count | Graphs |
|:--|--:|:--|
| Frustrated loops (Hen et al., *Phys. Rev. A* 92, 042325, 2015) | 14 | Pegasus P6 and P16, Zephyr Z4 and Z12, IBM Eagle 127 and Heron r2 156, heavy-hex d=15, 3D cubic lattice L = 8, 16; loop densities α = 0.1–0.3, couplings |J| ≤ 3 |
| Integer Wishart ensemble (after Hamze et al., *Phys. Rev. E* 101, 052102, 2020) | 14 | complete graphs, n = 32 … 512, α = m/n = 0.25 and 0.5 |

How the optimum is known: see the docstrings of `planted_frustrated_loops` and
`planted_wishart_pm1` in `qvsc/maxcut/generators.py`. In short, the energy is a sum of terms each of
which the planted configuration minimises (loops), or a squared norm that the planted configuration
sends to zero (Wishart), so no cut can beat it. `upper_bound` = `reference_value` = the optimum.

On the integer Wishart instances with α = 0.25–0.5, simulated annealing and tabu search already
miss the optimum at n = 128 with a few seconds per instance: they are the Max-Cut counterpart of
the EVIL graphs of the MIS track, small enough for today's quantum hardware and hard for classical
heuristics, with a certified answer.

**The seeds are secret.** Anyone with the seed could regenerate the planted cut. QvsC publishes the
optimum value and the SHA-256 of the planted solution file (`planted.csv`); the files themselves are
kept by the maintainers and can be published later, which proves the values were fixed in advance.

## `index.csv` columns

| Column | Meaning |
|:--|:--|
| `name` | instance id = file name without `.mc.gz`; solutions must be named `<name>.sol` |
| `family` | sub-folder of `instances/` |
| `tracks` | `;`-separated leaderboard tracks: `all`, `literature`, `hardware-native`, `qaoa`, `planted`, `gate-scale` (n ≤ 156) |
| `n`, `m` | vertices, edges (after merging parallel edges and removing zero weights and self-loops) |
| `weights` | `unit`, `pm1` (±1), `positive` or `integer` |
| `best_known` | best cut backed by a verified solution file in this repository |
| `status` | `optimal` (best_known = upper_bound), `best-known`, `below-reference` (best_known < reference_value), `open` (no solution yet) |
| `upper_bound` | proven upper bound (CP-SAT, exhaustive search, or the planted optimum) |
| `reference_value` | best value in the literature, or the planted optimum; not backed by a solution file here |
| `reference_source` | where `reference_value` comes from |
| `record_source` | submission that first reached `best_known` |
| `sha256` | content hash of the graph (independent of comments, edge order and compression) |
| `origin`, `license` | where the graph comes from and under which terms |

To rebuild everything:

```bash
pip install dwave-networkx rustworkx qiskit-ibm-runtime     # only for the hardware topologies
python problems/maxcut/scripts/import_sources.py --hardware
```

The literature instances are downloaded from `https://mqlibinstances.s3.amazonaws.com/`. Random
families use public string seeds (shown in each file's header) and pure-Python generators, so they
are reproduced bit for bit; `sha256` lets you check. Planted instances need the maintainers' secret
(`--planted`, with `QVSC_PLANTED_SECRET` set) and are otherwise kept as they are.
